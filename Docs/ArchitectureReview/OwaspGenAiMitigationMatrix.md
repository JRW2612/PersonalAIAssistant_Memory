# OWASP GenAI Top 10: implementation mapping

This matrix maps the OWASP GenAI risks to the running Memory service. **Implemented** means a control is present in the repository and its enforcement point is identified. It does not by itself establish operating effectiveness; production deployment, configuration, and tests remain required.

| OWASP ID | Agent scenario | Repository control | Status and evidence | Remaining action |
| --- | --- | --- | --- | --- |
| LLM01 — Prompt Injection | A calendar invite instructs an agent to forward email externally. | Prompt-injection scanning rejects memory write payloads; the gateway redacts sensitive request content before forwarding. | **Partial.** `PromptInjectionScanningBehavior` blocks detected injection patterns and audits the event. The gateway has a single request scrub/forward pass. | Add instruction/data delimiters at prompt assembly, a second independent guardrail evaluation, and tests using indirect-injection fixtures such as calendar/email bodies. |
| LLM02 — Sensitive Information Disclosure | An agent retrieves memory belonging to another tenant. | JWT user/tenant context, owner checks, user-scoped Qdrant filter, AES-GCM encryption for event/read-model payloads. | **Partial.** Qdrant filters on `userId`; authorization checks tenant on authorized command paths. | Put an immutable `tenantId` payload on every vector point and require both tenant and user filters for every search. Add cross-tenant retrieval tests and remove public database port exposure in production. |
| LLM03 — Supply Chain Vulnerabilities | An unverified LoRA adapter is downloaded and evaluated. | No adapter/model artifact installation path exists in this service. | **Not applicable today / required before enabling model artifacts.** | Require Sigstore/cosign verification, immutable digest allow-lists, provenance attestations, malware scanning, and the isolated execution profile before any adapter is accepted. |
| LLM04 — Data and Model Poisoning | False records are ingested to bias future responses. | Memory ingestion normalization/redaction/classification, DLP and prompt-injection checks, append-only event store, consolidation provenance links. | **Partial.** Ingested content is scrubbed before persistence and history is available through events. | Add source trust tiers, ingest anomaly scoring, moderation/quarantine state, reviewer workflow, and tamper-evident event integrity checks. |
| LLM05 — Improper Output Handling | Model-produced JavaScript is rendered in an administration page. | Strict JSON request/tool schemas; gateway returns provider responses without executing them; execution profile has no network and dropped capabilities. | **Partial.** The backend has no UI renderer or output executor. | Apply context-specific output encoding in every future HTML/SQL/shell consumer; validate model responses against operation-specific JSON schemas before use. Never interpolate model text into commands. |
| LLM06 — Excessive Agency | An agent deletes a production database without human confirmation. | API authorization, per-route policies, strict tool validation, and a non-networked execution sandbox profile. | **Partial.** No database-deletion tool is present. | Introduce an action registry with least-privilege service identities, risk classification, idempotency keys, and durable step-up approval for destructive/high-impact actions. Do not let prompts grant permissions. |
| LLM07 — System Prompt Leakage | Roleplay extracts proprietary guardrails. | Server-side JWT authorization, gateway authentication, and tool schema enforcement do not depend on prompt secrecy. | **Partial.** This is the correct authorization boundary. | Treat prompts as potentially public; keep secrets and access decisions outside prompts. Add regression tests that request system instructions and verify no credentials or protected context are returned. |
| LLM08 — Vector & Embedding Weaknesses | An attacker reconstructs source texts from inadequately protected embeddings. | Private compose backend network, Qdrant user filter, encrypted event/read-model payloads, authenticated API. | **Partial.** Embeddings themselves are not encrypted and Qdrant has no tenant payload filter. | Restrict Qdrant to its private network in production, enforce tenant/user payload filters, assess encryption-at-rest for Qdrant, and evaluate retrieval-quality impact before adding differential-privacy noise. |
| LLM09 — Misinformation / Hallucination | Agent fabricates security advice during an audit. | Retrieval service scores memory results; consolidation supports provenance links. | **Partial.** Retrieval has no mandatory source-attribution contract or verification pass. | Return source IDs/links with generated claims, require citations for audit/security responses, add deterministic policy/rule verification, and abstain when evidence is insufficient. |
| LLM10 — Unbounded Consumption | A user triggers recursive reasoning across providers. | API and gateway rate limits, provider max-token settings, HTTP timeouts, 2-second vector operation cancellation, resource-limited execution profile. | **Partial.** There is no agent loop yet, so depth/budget controls do not exist. | Add per-user/provider token and cost budgets, maximum tool-call/recursion depth, wall-clock deadlines propagated through requests, circuit breakers, and alerts on budget exhaustion. |

## Required production invariants

1. `AI_GATEWAY_INTERNAL_TOKEN` must be supplied as a deployment secret; applications must not hold provider API keys.
2. The API connects only to the private `backend` network. The gateway is the sole service connected to the egress network.
3. Any future code-execution adapter must invoke only the `execution-sandbox` Compose profile and must preserve its `network_mode: none`, `read_only`, `cap_drop: ALL`, and `no-new-privileges` settings.
4. Audit records must use hashes/metadata for prompts and outputs. Do not log raw prompts, outputs, credentials, or model chain-of-thought.
5. A release cannot claim tenant isolation until `tenantId` is propagated into storage and vector filters, and cross-tenant tests pass.
